§3.1–3.2

Why head, tail, and dummy nodes matter

A singly linked node stores a value and a next reference. Keeping both head and tail enables O(1) insertion at either end, but deleting a singly-linked tail requires finding its predecessor. In a doubly linked list, each node also has a prev reference and the dummy sentinel simplifies boundary cases.

§3.3

Space-efficient linked blocks

An SEList stores a small BDeque in each linked node. Here the teaching demo uses parameter b = 3 (capacity b+1 = 4 values per block). Insertion can push a value from one full block to the next; removal can borrow from a neighbor. Morin additionally uses spread/gather operations to keep nodes well occupied.

Supplementary animations based on Pat Morin’s Open Data Structures, Chapter 3. The SEList's block movement is a simplified demonstration of local propagation, not the full textbook spread/gather case analysis.
